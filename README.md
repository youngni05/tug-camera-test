# TUG 카메라 테스트 프로토타입

MediaPipe Pose로 실시간 골격 인식 + TUG(Timed Up and Go) 타이머 + 랜드마크 로깅/JSON 내보내기가 되는 단일 HTML 프로토타입입니다.

## 이 파일이 하는 일
- 카메라(전/후면) 켜기, 화면에 골격 오버레이
- "TUG 시작" ~ "TUG 종료" 구간의 모든 프레임에서 33개 포즈 랜드마크(x, y, z, visibility)와 3D world landmark를 기록
- 세션 종료 시 JSON으로 다운로드 (좌표, 총 소요시간, 프레임 수, 캘리브레이션 입력값 포함)
- 100% 온디바이스 처리 — 어떤 서버로도 영상/좌표를 전송하지 않음 (오프라인 모드 요건과 방향 일치)

## 왜 지금 이 형태인가
- 지표 계산(보행속도, 보폭, 균형 등) 알고리즘은 아직 확정 전 단계라, 우선 **원본 랜드마크가 안정적으로 잘 잡히는지**부터 실제 기기·조명·거리에서 확인하는 것이 먼저라고 판단했습니다.
- JSON을 받아두면 이후 지표 계산 로직을 오프라인에서 여러 버전으로 바꿔가며 같은 원본 데이터에 재적용해 비교할 수 있습니다.

## 호스팅 방법 (GitHub Pages)

1. 이 폴더(`tug-camera-test/`)를 repo에 그대로 추가하고 커밋/푸시
2. GitHub repo → Settings → Pages → Source를 `main` 브랜치, 루트 또는 해당 폴더로 설정
3. 몇 분 후 `https://<계정or조직>.github.io/<repo명>/tug-camera-test/` 로 접속
4. **반드시 HTTPS 주소로 접속** — 카메라 API(getUserMedia)는 HTTPS 또는 localhost에서만 동작합니다. `file://`로 직접 열면 카메라가 열리지 않습니다.

로컬에서 먼저 테스트하고 싶다면:
```bash
cd tug-camera-test
python3 -m http.server 8000
# 이후 브라우저에서 http://localhost:8000 접속 (localhost는 예외적으로 카메라 허용됨)
```

## 사용 순서
1. 삼각대 등으로 폰 고정, 측면 촬영 구도로 배치
2. 바닥에 2.4m 구간 표시 후, "카메라 시작" → 화면에 전체 동선이 들어오는지 확인
3. 측정 대상이 의자에 앉은 상태에서 "TUG 시작" 탭
4. 일어서기 → 2.4m 걷기 → 턴 → 복귀 → 착석까지 마친 후 "TUG 종료" 탭
5. "세션 JSON 다운로드" → repo의 `data/` 폴더 등에 저장, 커밋

## 알려진 제약 (v0.1)
- 화면 상 기준선 픽셀 길이 자동 측정 기능은 아직 없음 — 지금은 실측 거리(m)만 입력받아 JSON에 같이 저장해두고, 후처리 단계에서 랜드마크 좌표 기반으로 스케일 보정 예정
- 조명이 약하거나 역광이면 `visibility` 값이 낮게 나올 수 있음 — 세션 요약의 "평균 검출 신뢰도"로 촬영 품질 즉석 확인 가능
- 무릎 굴곡각, 몸통 기울기·골반 좌우 흔들림, 보폭·스트라이드는 페이지에서 바로 계산해 JSON `summary`에 저장됨. 보행속도 등 나머지 지표는 아직 없음
- **보행 구간 필터**: 골반이 빠르게 이동하는 구간만 "보행"으로 보고(`frames[].walking`), 걸음 수·무릎 최대각·흔들림은 그 구간만 사용. 임계값(`WALK_*` 상수)은 실측 데이터로 조정 필요하며, 보행 구간이 1초 미만이면 전체 구간으로 대체
- **기준선 보정**: "기준선 지정"으로 바닥 2.4m 구간 양 끝을 탭하면 화면 px↔m 비율을 잡아 보폭을 보정함. 카메라가 보행선과 수직인 **측면 촬영**에서만 유효하고, 사람이 기준선과 다른 깊이로 걸으면 오차가 생김. 추정치(MediaPipe world 좌표)와 보정값을 함께 표시해 서로 비교 가능
- 좌우 흔들림(몸통 기울기·골반 x)은 정면/후면 촬영에서만 의미가 있음 — 측면 촬영에서는 무릎 각도·보폭만 신뢰
